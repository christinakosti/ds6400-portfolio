1  Performance Measures

1.1 Varma & Simon (2006)

Title: Bias in error estimation when using cross-validation for model selection
Journal: BMC Bioinformatics

1.1.1 Problem

Cross-validation (CV) can be used to estimate how well a classifier will perform on independent data. However, ordinary CV can become biased when the same CV procedure is used both to choose the best model settings and to estimate the performance of the resulting model.

1.1.2 Why does the bias happen?

Choosing classifier parameters is part of the model training process. When several parameter values are tested using cross-validation, the value with the lowest CV error is selected. Because this minimum is chosen from several CV estimates, it may be too optimistic and underestimate the true prediction error. The authors call this parameter selection bias.

1.1.3 What do the authors propose instead?

The classifier parameter tuning should be treated as part of the model training procedure and therefore repeated inside the cross-validation process.

They use nested cross-validation, which contains two CV loops:

  • Inner CV: selects the optimal classifier parameters.
  • Outer CV: estimates the prediction error of the tuned classifier.

This separates model tuning from model evaluation and reduces the bias in the estimated prediction error.

1.1.4 Study design

A simulation study was used so they could compare the estimated prediction error with the true error.

The authors generated at least 1,000 simulated datasets each containing:

  • 40 samples
  • 20 samples in class 1 and 20 in class 2
  • 6,000 simulated gene-expression features

They considered two types of datasets:

  • Null datasets: there was no true difference between the two classes, so classification should perform at about chance level.
  • Non-null datasets: 10 of the 6,000 features had a true difference between the classes, so there was some real predictive signal.

They then applied the classification and cross-validation procedures to these simulated datasets and compared the estimated errors with performance on independent test data.

1.1.5 Classifier implementation

1.1.5.1 Shrunken Centroids

For the Shrunken Centroids classifier, the authors varied the tuning parameter Δ between 0.01 and 1. For each value of Δ, they calculated the 10-fold CV error and selected the value with the minimum error.

\[ \Delta^* = \arg\min_{\Delta} CV(\Delta) \]

They then trained the optimized classifier on all 40 training samples using the selected Δ* and tested it on 20,000 independent samples to estimate its true prediction error.

1.1.5.2 Support Vector Machine (SVM)

For the SVM, they tuned two parameters, C and γ. They used Leave-One-Out Cross-Validation (LOOCV) to calculate the prediction error for different combinations of these parameters and selected the combination with the minimum LOOCV error.

\[ (C^*, \gamma^*) = \arg\min_{C,\gamma} CV(C,\gamma) \]

The optimized SVM was then trained on all 40 samples and evaluated on 20,000 independent test samples to estimate the true error.

1.1.6 Nested cross-validation implementation

A nested cross-validation procedure was then evaluated in which the parameter-tuning step was repeated inside an outer CV loop.

For the Shrunken Centroids classifier, one sample was left out from the 40-sample dataset. The remaining 39 samples were used to select the optimal value of Δ using 10-fold CV. The classifier was then trained on those 39 samples using the selected Δ and used to predict the class of the one sample that had been left out.

This process was repeated until each of the 40 samples had been left out once. The average error across the 40 outer predictions was used as the nested CV error estimate.

The same nested-CV principle was also applied to the optimized SVM classifier.

In this setup the inner CV loop is used for parameter tuning and the outer CV loop is used to estimate prediction error.

1.1.7 Main findings

For the null datasets, the true prediction error was approximately 50%, because there was no real difference between the two classes.

However, after tuning the classifiers, the average CV error estimates were lower than the true error:

  • Shrunken Centroids: mean CV error = 37.8%
  • SVM: mean CV error = 41.7%
  • True error for both classifiers = 50.0%

This shows that using the minimum CV error after parameter tuning made the classifiers appear more accurate than they really were on independent data.

Figure 1 shows this bias for the optimized Shrunken Centroids classifier.

Source: Varma & Simon (2006), Figure 1.

Nested cross-validation produced error estimates that were much closer to the true error.

For the Shrunken Centroids classifier on null data:

  • Nested CV error = 54.2%
  • True error = 50.0%

Source: Varma & Simon (2006), Figure 3.

For the SVM classifier on non-null data:

  • Nested CV error = 35.3%
  • True error = 32.0%

Their results showed that nested CV substantially reduced the bias in the estimated prediction error.

1.1.8 Main conclusion: stop doing X, start doing Y

Stop: using the minimum cross-validation error obtained during parameter tuning as the final estimate of how well the optimized classifier will perform on independent data.

Start: treat parameter tuning as part of the training process and use nested cross-validation, where the inner CV loop tunes the classifier and the outer CV loop estimates prediction error.

Takeaway: Nested CV provides an almost unbiased estimate of the true error of an optimized classifier.

1.1.9 Proposed computational exploration

For my computational exploration, I plan to develop a simpler simulation that demonstrates the parameter-selection bias described in the paper.

I will simulate a binary classification problem with two equally sized classes and no true difference in the predictor distributions between the classes. Therefore, the true classification error should be approximately 50%.

I will use a k-nearest neighbors (kNN) classifier and treat the number of neighbors, k, as the tuning parameter. Each simulated training dataset will contain 40 observations, with 20 observations in each class. I will compare several candidate values of k (for example, 1, 3, 5, 7, and 9). Then, I will:

  1. Generate a training dataset of 40 observations from two equally sized classes with no true difference in their predictor distributions.
  2. Use 10-fold cross-validation to compare several values of k and select the value with the lowest CV error.
  3. Record this minimum CV error.
  4. Use nested cross-validation with 10-fold CV in the inner loop to select k and LOOCV in the outer loop to estimate prediction error.
  5. Select k using 10-fold CV on the full training dataset, train the optimized classifier on all 40 observations, and evaluate it on a large independently simulated test dataset to approximate the true prediction error.
  6. Repeat the simulation 500 times and compare the distributions of the three error estimates.

The main question will be whether the minimum CV error after tuning systematically underestimates the true prediction error, and whether nested CV produces an estimate closer to the truth.

1.1.10 Planned figure

I plan to create a figure comparing the prediction-error estimates obtained from:

  1. Minimum CV error after tuning
  2. Nested CV
  3. Independent test-set error

The figure will summarize the distribution of these errors across repeated simulations.

Because the simulated data will contain no true class difference, the independent test-set error should be approximately 50%. A persuasive result would show that the minimum CV error after tuning tends to underestimate this true error, while the nested-CV error remains closer to it.

1.1.11 Computational exploration

1.1.11.1 Phase 1: Simulating the data

I first simulate a binary classification problem with 40 observations that are equally divided between classes A and B. The two predictors are generated from the same distribution for both classes, so they contain no true information about class membership. This creates a null setting in which the expected classification error is approximately 50%.

class <- factor(rep(c("A", "B"), each = 20)) # Creates 40 class labels: 20 A and 20 B

table(class)
class
 A  B 
20 20

The class counts confirm that the simulated dataset is balanced, with 20 observations in class A and 20 in class B.

Next, I generate two continuous predictors, x1 and x2, from a standard normal distribution with mean 0 and standard deviation 1. Because both classes use the same distribution, the predictors contain no true class information and any apparent separation is due to chance.

Mathematically, for each predictor \(j=1,2\),

\[ X_{ij} \mid Y_i=A \sim N(0,1) \qquad \text{and} \qquad X_{ij} \mid Y_i=B \sim N(0,1). \]

set.seed(123) # Keeps data reproducible

x1 <- rnorm(40, mean = 0, sd = 1) # Generates one x1 value per observation from N(0,1)
x2 <- rnorm(40, mean = 0, sd = 1) # Generates one x2 value per observation from N(0,1)

Each observation can now be represented by its predictor vector \(\mathbf{X}_i\) and class label \(Y_i\), where

\[ \mathbf{X}_i = (X_{i1}, X_{i2}) \in \mathbb{R}^2, \qquad Y_i \in \{A,B\}. \]

Here, \(\mathbf{X}_i\) contains the two predictor values for observation \(i\), while \(Y_i\) indicates whether that observation belongs to class A or B. The full simulated dataset, denoted by \(\mathcal{D}\), can therefore be written as

\[ \mathcal{D} = \{(\mathbf{X}_i, Y_i)\}_{i=1}^{40}. \]

I combine these values into a data frame so that each row represents one simulated observation.

sim_data <- data.frame(
  class = class,
  x1 = x1,
  x2 = x2
) # Creates the simulated data frame

At this point, each of the 40 observations has a class label and two predictor values, but the predictors were generated independently of class.

To visualize the null setting, I plot x1 against x2 and distinguish the two classes by color.

plot(
  sim_data$x1,
  sim_data$x2,
  col = c("steelblue", "tomato")[sim_data$class],
  pch = 19,
  cex = 1.2,
  xlab = "Predictor x1",
  ylab = "Predictor x2",
  main = "Null Simulation: No True Class Separation"
)

legend(
  "topright",
  legend = c("Class A", "Class B"),
  col = c("steelblue", "tomato"),
  pch = 19,
  bty = "n"
)

The two classes overlap substantially, with no clear separation between A and B. This is consistent with the way the data were simulated: the predictors contain no true class signal.

1.1.11.2 Phase 2: k-nearest neighbors classification

I next use k-nearest neighbors (kNN) to classify the observations. kNN predicts the class of a new observation by finding the \(k\) observations in the training data that are closest to it and assigning the class that is most common among those neighbors.

Because there are two predictors, the distance between two observations can be calculated using Euclidean distance:

\[ d(\mathbf{X}_i,\mathbf{X}_j) = \sqrt{(X_{i1}-X_{j1})^2 + (X_{i2}-X_{j2})^2}. \]

Smaller values of \(k\) make the classifier depend on fewer nearby observations, while larger values use more neighbors. I compare five possible values of \(k\):

\[ \mathcal{K} = \{1,3,5,7,9\}. \]

library(class) # Loads the package containing the knn() function

k_values <- c(1, 3, 5, 7, 9) # Candidate values of k

x <- sim_data[, c("x1", "x2")] # Keeps only the predictors used by kNN

1.1.11.3 Phase 3: Choosing k with cross-validation

To compare the candidate values of \(k\), I use 10-fold cross-validation. The 40 observations are divided into 10 folds, with each fold containing two observations from class A and two from class B.

set.seed(456) # Makes the random fold assignment reproducible

fold_id <- integer(40) # Creates a vector with one position for each observation

fold_id[class == "A"] <- sample(rep(1:10, each = 2))
fold_id[class == "B"] <- sample(rep(1:10, each = 2))
# Randomly assigns each class across 10 folds, with 2 A and 2 B per fold

Each observation is now assigned to one of the 10 folds. During cross-validation, one fold is held out for testing while the remaining nine folds are used for training. This process is repeated until every fold has served as the test fold.

To compare the candidate values of \(k\), I need to store the cross-validation error calculated for each one.

cv_error <- numeric(length(k_values)) # Creates space to store one CV error for each value of k

For each candidate value of \(k\), I estimate its classification error using the 10 folds. Within each fold, the model is trained on 36 observations and tested on the 4 observations that were held out.

For a given fold, the classification error is the proportion of held-out observations that are classified incorrectly:

\[ \widehat{\mathrm{Err}}_{f}(k) = \frac{1}{n_f} \sum_{i \in f} I(\widehat{Y}_i \neq Y_i), \]

where \(n_f\) is the number of observations in fold \(f\), and \(I(\widehat{Y}_i \neq Y_i)\) equals 1 when an observation is classified incorrectly and 0 when it is classified correctly.

The 10-fold cross-validation error for a given value of \(k\) is then the average error across the 10 folds:

\[ \widehat{\mathrm{Err}}_{\mathrm{CV}}(k) = \frac{1}{10} \sum_{f=1}^{10} \widehat{\mathrm{Err}}_{f}(k). \]

for (j in seq_along(k_values)) { # Repeats once for each candidate value of k
  
  fold_error <- numeric(10) # Stores one error for each of the 10 folds
  
  for (fold in 1:10) { # Repeats the process for each fold
    
    train_idx <- fold_id != fold # Observations used for training
    test_idx  <- fold_id == fold # Observations held out for testing
    
    pred <- knn(
      train = x[train_idx, ],
      test = x[test_idx, ],
      cl = class[train_idx],
      k = k_values[j]
    )
    
    fold_error[fold] <- mean(pred != class[test_idx]) # Error in the held-out fold
  }
  
  cv_error[j] <- mean(fold_error) # Average error across all 10 folds
}

For each candidate value of \(k\), the model is evaluated across all 10 folds. The errors from the 10 folds are then averaged to produce one cross-validation error for that value of \(k\). This process is repeated for each candidate value of \(k\).

I combine the candidate values of \(k\) and their corresponding cross-validation errors into a table so that their performance can be compared directly.

cv_results <- data.frame(
  k = k_values,
  cv_error = cv_error
) # Combines each candidate k with its corresponding 10-fold CV error

cv_results # Shows the CV error for each k
  k cv_error
1 1    0.525
2 3    0.425
3 5    0.525
4 7    0.525
5 9    0.575

Among the five candidate values, k = 3 has the lowest cross-validation error at 0.425, meaning that 42.5% of the held-out observations were misclassified on average.

I select the value of \(k\) with the smallest cross-validation error. This can be written as

\[ k^* = \underset{k \in \mathcal{K}}{\arg\min} \ \widehat{\mathrm{Err}}_{\mathrm{CV}}(k). \]

Here, \(k^*\) represents the value of \(k\) that appears to perform best according to cross-validation.

best_index <- which.min(cv_error) # Finds the position of the smallest CV error

best_k <- k_values[best_index] # Uses that position to identify the corresponding k

best_k
[1] 3
min_cv_error <- min(cv_error) # Stores the lowest 10-fold CV error across all candidate k values

min_cv_error
[1] 0.425

For this particular simulated dataset, cross-validation selects k = 3, with a minimum estimated error of 42.5%.

1.1.11.4 Phase 4: Nested cross-validation

The minimum cross-validation error calculated above is based on the same cross-validation procedure that was used to choose \(k\). Because the best-performing value is selected from several candidates, this minimum error may make the classifier appear better than it really is.

To separate model selection from model evaluation, I next use nested cross-validation. The procedure has two levels:

  1. The inner cross-validation chooses the best value of \(k\).
  2. The outer cross-validation evaluates the classifier using an observation that was not involved in choosing \(k\).

In this simulation, the outer procedure uses leave-one-out cross-validation (LOOCV). One of the 40 observations is held out, leaving 39 observations for model selection. Ten-fold cross-validation is then performed using only those 39 observations to choose \(k\). The selected value of \(k\) is used to predict the single untouched outer observation.

This process is repeated until every observation has been held out once.

Illustration: How nested cross-validation works

The diagram below shows how the inner and outer stages work together.

Because the same 10-fold cross-validation procedure is used whenever I need to compare candidate values of \(k\), I place this repeated computation inside a reusable function. The function takes a training dataset, evaluates all candidate values of \(k\), and returns both the selected \(k\) and its minimum cross-validation error.

select_k_cv <- function(x_train, y_train, k_values) { # Uses 10-fold CV to compare candidate values of k
  
  fold_id <- integer(length(y_train)) # Creates one fold label per training observation
  
  fold_id[y_train == "A"] <- sample(
    rep(1:10, length.out = sum(y_train == "A"))
  )
  
  fold_id[y_train == "B"] <- sample(
    rep(1:10, length.out = sum(y_train == "B"))
  )
  # Distributes observations from each class approximately evenly across the 10 folds
  
  cv_error <- numeric(length(k_values)) # Stores one CV error for each candidate k
  
  for (j in seq_along(k_values)) { # Tries each candidate value of k
    
    observation_error <- numeric(length(y_train)) # Stores prediction errors for this k
    
    for (fold in 1:10) { # Uses each fold once for testing
      
      train_idx <- fold_id != fold # Observations used for training
      test_idx <- fold_id == fold # Observations held out for testing
      
      pred <- knn(
        train = x_train[train_idx, , drop = FALSE],
        test = x_train[test_idx, , drop = FALSE],
        cl = y_train[train_idx],
        k = k_values[j]
      )
      
      observation_error[test_idx] <- as.numeric(
        pred != y_train[test_idx]
      ) # Records 1 for an incorrect prediction and 0 for a correct prediction
    }
    
    cv_error[j] <- mean(observation_error) # Calculates CV error for this k
  }
  
  list(
    best_k = k_values[which.min(cv_error)], # k with the lowest CV error
    min_cv_error = min(cv_error) # Corresponding minimum CV error
  )
}

The outer leave-one-out procedure is also repeated whenever nested cross-validation is performed. I therefore place this procedure inside a reusable function. For each held-out observation, the function uses select_k_cv() on the remaining observations to choose \(k\), predicts the untouched observation, and finally averages the outer prediction errors.

nested_cv_once <- function(x, y, k_values) { # Runs nested CV on one dataset
  
  nested_error <- numeric(length(y)) # Stores one outer prediction error per observation
  
  for (i in seq_along(y)) { # Holds out each observation once
    
    outer_train_idx <- seq_along(y) != i # The remaining 39 observations
    outer_test_idx <- seq_along(y) == i # The one untouched observation
    
    x_outer <- x[outer_train_idx, , drop = FALSE]
    y_outer <- y[outer_train_idx]
    
    inner_result <- select_k_cv(
      x_train = x_outer,
      y_train = y_outer,
      k_values = k_values
    ) # Chooses k using only the 39 outer-training observations
    
    best_inner_k <- inner_result$best_k # Extracts the selected k
    
    pred_outer <- knn(
      train = x_outer,
      test = x[outer_test_idx, , drop = FALSE],
      cl = y_outer,
      k = best_inner_k
    ) # Predicts the untouched outer observation
    
    nested_error[i] <- pred_outer != y[outer_test_idx]
    # Records whether the outer prediction was incorrect
  }
  
  mean(nested_error) # Returns the average error across all outer predictions
}

I now apply the nested cross-validation procedure to the original 40-observation dataset.

set.seed(789) # Makes the inner CV fold assignments reproducible

nested_cv_error <- nested_cv_once(
  x = x,
  y = class,
  k_values = k_values
) # Runs nested CV on the original simulated dataset

nested_cv_error
[1] 0.65

The nested cross-validation error for this particular simulated dataset is 65%. Unlike the minimum ordinary cross-validation error, this estimate is based on outer observations that were not used to choose \(k\), so model selection and model evaluation are kept separate.

1.1.11.5 Phase 5: Evaluating on an independent test set

Nested cross-validation provides an estimate of model performance using only the original 40 observations. However, because the data are simulated, I can also generate a large independent test set that was never used for training or model selection.

In the null setting, the predictors contain no true class information, so the expected classification error on new observations is approximately 50%. I therefore use the independent test set as a benchmark for the error estimates obtained from cross-validation.

I generate 20,000 new observations using the same data-generating process as before, with 10,000 observations from class A and 10,000 from class B.

set.seed(999) # Makes the independent test set reproducible

test_class <- factor(rep(c("A", "B"), each = 10000)) # Creates 20,000 balanced class labels

test_x <- data.frame(
  x1 = rnorm(20000, mean = 0, sd = 1),
  x2 = rnorm(20000, mean = 0, sd = 1)
) # Generates two predictors with no true class signal

The model is then trained on all 40 original observations using the value of \(k\) selected by ordinary cross-validation. It is evaluated on the 20,000 new observations.

test_pred <- knn(
  train = x,
  test = test_x,
  cl = class,
  k = best_k
) # Predicts the classes of the independent test observations

The independent test-set error is the proportion of the 20,000 predictions that are incorrect:

\[ \widehat{\mathrm{Err}}_{\mathrm{test}} = \frac{1}{20000} \sum_{i=1}^{20000} I(\widehat{Y}_i^{\mathrm{test}} \neq Y_i^{\mathrm{test}}). \]

test_error <- mean(test_pred != test_class) # Proportion of independent test observations classified incorrectly

test_error
[1] 0.498

Because the independent test observations were not involved in either training or selecting \(k\), this error provides a benchmark for how the selected classifier performs on new data.

1.1.11.6 Phase 6: Repeating the simulation

The results above are based on a single simulated dataset. Because a different random sample of 40 observations could produce different cross-validation errors, I repeat the entire simulation many times to examine the behavior of each error estimate across repeated samples.

For each repetition, I generate a new dataset of 40 observations and repeat the same three evaluations:

  1. Select \(k\) using ordinary 10-fold cross-validation and record the minimum CV error.
  2. Estimate error using nested cross-validation.
  3. Evaluate the selected model on a new independent test set of 20,000 observations.

Because the cross-validation procedures were defined as reusable functions in Phase 4, I can apply them directly to each new simulated dataset.

run_one_simulation <- function() { # Runs the entire experiment once
  
  y <- factor(rep(c("A", "B"), each = 20))
  # Creates 40 balanced class labels: 20 A and 20 B
  
  x_sim <- data.frame(
    x1 = rnorm(40, mean = 0, sd = 1),
    x2 = rnorm(40, mean = 0, sd = 1)
  ) # Generates a new null dataset
  
  ordinary <- select_k_cv(
    x_train = x_sim,
    y_train = y,
    k_values = k_values
  ) # Runs ordinary 10-fold CV on all 40 observations
  
  nested_error <- nested_cv_once(
    x = x_sim,
    y = y,
    k_values = k_values
  ) # Estimates error using nested cross-validation
  
  test_y <- factor(rep(c("A", "B"), each = 10000))
  # Creates 20,000 balanced labels for independent testing
  
  test_x <- data.frame(
    x1 = rnorm(20000, mean = 0, sd = 1),
    x2 = rnorm(20000, mean = 0, sd = 1)
  ) # Generates a new independent test set
  
  test_pred <- knn(
    train = x_sim,
    test = test_x,
    cl = y,
    k = ordinary$best_k
  ) # Uses the k selected by ordinary CV
  
  test_error <- mean(test_pred != test_y)
  # Calculates the independent test-set error
  
  c(
    min_cv_error = ordinary$min_cv_error,
    nested_cv_error = nested_error,
    test_error = test_error
  ) # Returns the three error estimates
}

1.1.12 Conclusions

Across 500 simulated null datasets, the minimum ordinary cross-validation error averaged 42.1%, while the independent test-set error averaged 49.98%. This shows that reporting the minimum CV error after tuning made the classifier appear more accurate than it actually was on new data.

Nested cross-validation produced an average error of 51.27%, which was much closer to the independent test-set error. This supports the main point of Varma and Simon (2006): when cross-validation is used both to tune a model and to report its performance, the minimum CV error can be optimistically biased. In this simulation, nested cross-validation provided an estimate closer to the independent test-set error.

In this small-sample simulation, nested cross-validation was also more variable across repetitions. Its main advantage here was therefore reducing bias rather than producing a more stable estimate.
